# CQA — оценка качества диалогов

Прототип Conversation Quality Analytics для хакатона Freedom Broker. Система оценивает работу оператора в чатах и звонках по настраиваемому чек-листу, показывает баллы, объяснения и реплики-доказательства, а также поддерживает апелляции и пересмотр оценки.

Сценарий защиты и порядок действий на контрольном часе — [docs/DEMO.md](docs/DEMO.md).

## Возможности

**Контур 1. Оценка**
- Загрузка диалогов из API организаторов по любому `group_id` (DEV, контрольный набор и т.д.) или импорт из файлов: JSON, CSV/TSV, Excel (.xlsx), TXT — по нескольку файлов сразу. Ранее загруженные наборы и оценки сохраняются.
  - CSV / Excel: одна строка = одна реплика; обязательны столбцы `speaker` и `text`, по желанию `conversation_id`, `timestamp`, `channel`, `language`, `audio_url` (русские названия «диалог», «роль», «текст», «время» тоже подходят). Шаблон: `/api/dataset/template.csv`.
  - TXT: строки «[00:12] Оператор: текст»; несколько диалогов разделяются строкой «### id».
  - Язык, если он не указан в файле, определяется автоматически или задаётся при импорте. Примеры — в `samples/`.
- Редактор чек-листа: критерии, формулировки, раздел, вес, тип ответа (Да/Нет, шкала, грубая ошибка), доступность N/A и его условие, ступени шкалы. Каждое сохранение создаёт новую версию.
- Оценка одного диалога или всех неоценённых с выбором версии чек-листа. Поддерживаются RU, KZ, EN; реплики бота и системы — контекст.
- Результат по каждому критерию: ответ, баллы с учётом перераспределения, вес, объяснение, цитата-доказательство или проверенный участок разговора (для пропущенного действия), причина N/A. Итог, результаты разделов и отдельная отметка грубой ошибки.

**Контур 2. Работа с результатом**
- Карточка диалога: клик по цитате прокручивает к реплике и подсвечивает фрагмент; у звонков — плеер и перемотка к реплике (если запись доступна напрямую) или ссылка на плеер организаторов.
- Апелляция по критерию с комментарием. Проверяющий видит спорную оценку, объяснение, комментарий и фрагмент диалога, подтверждает или меняет оценку с указанием причины, видит пересчёт итога до сохранения.
- В карточке видны исходная оценка модели, решение и финальный результат. История оценок сохраняется.
- Фильтры: набор, язык, канал, статус, «только с грубыми ошибками». Экспорт результатов в JSON: `/api/export?group_id=DEV`.

## Как устроена оценка

1. Сервер передаёт модели чек-лист и транскрипт, где каждая реплика имеет ID (`m1`, `m2`, …).
2. Модель (OpenAI, структурированный JSON) возвращает по каждому критерию ответ, объяснение, цитаты и проверенный участок.
3. Сервер проверяет ответ: все критерии на месте, ответ допустим (N/A только где разрешён, значение шкалы — из списка), каждая цитата **дословно** есть в указанной реплике. При ошибке — одна попытка исправления с перечнем ошибок.
4. Если цитаты так и не подтвердились — статус «Требует проверки» с перечнем проблем, баллы помечаются как непроверенные.
5. Баллы и итог считает сервер (Decimal): «Да» = полный вес, «Нет» = 0, шкала пропорционально весу, вес N/A перераспределяется (максимум 100), округление до 2 знаков, грубая ошибка — отдельный флаг.
6. Ошибка модели или сети не превращается в нулевую оценку: статус «Ошибка». Если задан запасной провайдер (Gemini), оценка повторяется им.

## Звонки: анализ записи

Если в `.env` задан `GEMINI_API_KEY`, звонок оценивается **по аудиозаписи вместе с транскриптом**: сервер берёт mp3 со страницы плеера организаторов и передаёт его модели Gemini (`GEMINI_MODEL`). Модель:
- оценивает критерии по тому, что реально прозвучало (тон, паузы, перебивания, ясность речи);
- заполняет блок «Речь оператора по записи звонка»: интонация, дикция и грамотность, темп и паузы, вежливость, замечания;
- отмечает места, где автоматическая расшифровка ошиблась («Вероятно сказано: …») — такие ошибки не засчитываются оператору.

Цитаты-доказательства по-прежнему берутся дословно из транскрипта и проверяются сервером. Если запись недоступна или Gemini не ответил, звонок оценивается по тексту обычной моделью, а в карточке указана причина. Выключить: `AUDIO_ANALYSIS=off`.

## Сдача результатов

Блок «Сдача результатов организаторам» на странице «Диалоги» выгружает оценки в формате JSON 1.0 из приложения к гайду:
`results/dev/results.json` (DEV) и `results/prod/results.json` (контрольный набор). Кнопка «Проверить» показывает число записей и проблемы формата,
«Сохранить в репозиторий» записывает файл; затем `git add results && git commit && git push`.

- Коды критериев: `contact, discovery, identification, consultation, empathy, dialogue, closure, critical` (наши `c1…c8`).
- `value`: true / false / null (N/A) или ступень шкалы до учёта веса; `evidence_turns` — номера реплик с 1 по исходному транскрипту.
- По умолчанию выгружается оценка модели; флажок «С учётом апелляций» — с решениями проверяющих.
- Не оценённый диалог попадает в файл со `status: "error"`, а не с нулём. Название команды — `TEAM_NAME` в `.env`.

Порядок на контрольном часе: ввести выданный `group_id` → «Загрузить из API организаторов» → «Оценить неоценённые» → «Проверить» → «Сохранить в репозиторий» (results/prod) → push.

## Модель и стоимость

Модель выбирается в интерфейсе (список — `OPENAI_MODELS` в `.env`) отдельно для каждой оценки или пакета; в карточке видно, какой моделью поставлена оценка.

**Модель:** OpenAI `gpt-4o-mini` (внешний API). **Примерная стоимость одной оценки** с учётом всех вызовов (включая попытку исправления), по замеру на 65 диалогах DEV:

| Диалог | Токены (вход / выход) | Стоимость |
|---|---|---|
| Чат | ≈ 2 000 / 450 | ≈ $0,0006 |
| Звонок | ≈ 7 500 / 950 | ≈ $0,0017 |
| Весь DEV (65) | 156 тыс. / 32 тыс. | ≈ $0,044 |

Цены `gpt-4o-mini`: $0,15 вход / $0,60 выход за 1 млн токенов.

Модель по умолчанию меняется в `.env` (`OPENAI_MODEL`). Расход токенов и примерная стоимость каждой оценки (все вызовы, включая попытку исправления) показываются в карточке. Цены задаются в `.env`; сверьте их с актуальным прайсом OpenAI.

## Запуск (Windows)

Нужен Python 3.11+.

1. Дважды кликните `start.bat` — он создаст окружение, установит зависимости, создаст `.env` и откроет http://127.0.0.1:8765.
2. Откройте `.env` и укажите:
   - `OPENAI_API_KEY` — ключ OpenAI;
   - `ORGANIZER_API_URL` — ссылку GET из методички (без неё можно импортировать JSON вручную, пример — `samples/demo-dialogs.json`).
3. Перезапустите `start.bat`.

Вручную (любая ОС):

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Linux/macOS: .venv/bin/python
cp .env.example .env
.venv/Scripts/python run.py
```

Тесты: `.venv/Scripts/python -m pytest -q`. Документация API: http://127.0.0.1:8765/api/docs.

## Структура

```
app/main.py              API (FastAPI) и раздача интерфейса
app/evaluator.py         промпт, вызов модели, проверка доказательств
app/llm.py               провайдеры OpenAI / Gemini, токены и стоимость
app/scoring.py           проверка чек-листа и расчёт итога
app/dataset.py           загрузка из API организаторов и импорт
app/default_checklist.py начальный чек-лист из PDF
web/                     интерфейс на HTML/CSS/JS без сборки
samples/                 синтетические диалоги для проверки
tests/                   тесты расчёта и API
```

Интерфейс — чистые HTML/CSS/JS без фреймворков и сборки, монтируется в один контейнер `#cqa-root` и обращается к серверу по относительным путям `/api`, поэтому его можно адаптировать как HTML-ресурс Dynamics 365. Данные хранятся в SQLite (`data/cqa.sqlite`). Авторизации нет — прототип рассчитан на локальный запуск.
