# CQA — контроль качества диалогов · Freedom Broker

Прототип **Conversation Quality Analytics** для хакатона Freedom Broker CQA. Система оценивает работу оператора в чатах и звонках по настраиваемому чек-листу. Она показывает ответ по каждому критерию, баллы, объяснение и реплику-доказательство, поддерживает апелляции и пересмотр оценки и выгружает результаты в формате организаторов.

## Быстрый старт (Windows)

Нужен Python 3.11+.

1. Дважды кликните `start.bat`. Он создаст окружение, установит зависимости, скопирует `.env.example` в `.env` и откроет http://127.0.0.1:8765.
2. Откройте `.env` и заполните:
   - `OPENAI_API_KEY` — ключ OpenAI (оценка чатов);
   - `ORGANIZER_API_URL` — ссылка «Открыть GET для DEV» из методички (параметр `group_id` сервер подставит сам);
   - `GEMINI_API_KEY` — по желанию, для анализа записей звонков ([получить ключ](https://aistudio.google.com/apikey));
   - `TEAM_NAME` — название команды для `results.json`.
3. Перезапустите `start.bat`. Вверху справа должны загореться индикаторы «API организаторов» и «Модель ИИ».

Вручную (любая ОС):

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Linux/macOS: .venv/bin/python
cp .env.example .env
.venv/Scripts/python run.py
```

Тесты: `.venv/Scripts/python -m pytest -q`. Документация API: http://127.0.0.1:8765/api/docs.

## Как пользоваться

1. **Диалоги → «Загрузить из API организаторов»** (поле «Набор» = `DEV` или выданный `group_id`) либо **«Импорт из файлов»** (JSON, CSV/TSV, Excel, TXT).
2. Выберите версию чек-листа и модель (в левой панели или рядом с кнопкой) → **«Оценить неоценённые»**.
3. Откройте диалог: итог, разделы, критерии с объяснениями. Клик по цитате прокручивает транскрипт к реплике; у звонка ещё и перематывает запись.
4. Не согласны с критерием → **«Оспорить»**. Проверяющий в разделе **«Апелляции»** подтверждает или меняет оценку с причиной; итог пересчитывается.
5. **Чек-лист**: измените критерий, вес, тип, шкалу или N/A → «Сохранить новую версию» → выберите её при следующей оценке.
6. **Аналитика**: средний балл, где теряются баллы, распределение итогов, языки и каналы, грубые ошибки, худшие диалоги, стоимость.
7. **Сдача результатов** (страница «Диалоги»): «Проверить» → «Сохранить в репозиторий» → `git push`.

## Возможности

**Контур 1. Оценка**
- Загрузка из API организаторов по любому `group_id` через сервер (без проблем с CORS), с сохранением исходных ID и меток времени. Ранее загруженные наборы и оценки сохраняются, ненужный набор удаляется кнопкой корзины.
- Импорт из файлов: **JSON** (формат API), **CSV / TSV / Excel** (строка = реплика, обязательны «роль» и «текст»; шаблон — `/api/dataset/template.csv`), **TXT** («[00:12] Оператор: текст», диалоги разделяются «### id»). Язык определяется автоматически или задаётся при импорте. Примеры — `samples/`.
- Редактор чек-листа: название, формулировка, раздел, тип (Да/Нет, шкала, грубая ошибка), вес, N/A и его условие, ступени шкалы, порядок; добавление и удаление критериев. Каждое сохранение — новая версия; старые оценки остаются привязаны к своей.
- Оценка одного диалога или пакета, с выбором версии чек-листа и модели. RU, KZ, EN; реплики бота и системные события — контекст.
- Результат по каждому критерию: ответ, баллы после перераспределения, вес, объяснение, цитата-доказательство; для пропущенного действия — проверенный участок; для N/A — причина. Итог, результаты разделов, отдельный флаг грубой ошибки.

**Контур 2. Работа с результатом**
- Карточка диалога: переход к реплике и подсветка фрагмента; у звонков — плеер с перемоткой к реплике.
- Апелляция по критерию с комментарием → проверяющий видит спорную оценку, объяснение модели, комментарий и фрагмент диалога → подтверждает или меняет с причиной, видя новый итог до сохранения. В карточке — исходная оценка, решение и финальный итог.
- История оценок по каждому диалогу, фильтры (набор, язык, канал, статус, «только с грубыми ошибками»), аналитика, выгрузка результатов.

**Сверх обязательного**
- **Анализ записей звонков** (Gemini): оценка по тому, что реально прозвучало, блок «Речь оператора» (интонация, дикция, темп, вежливость) и пометки об ошибках автоматической расшифровки.
- Проверка доказательств: каждая цитата модели сверяется с текстом реплики; выдуманная цитата → статус «Требует проверки».
- Выбор модели (OpenAI / Gemini) и запасная модель при сбое провайдера.
- Раздел «Аналитика» и учёт стоимости каждой оценки.

## Как устроена оценка

1. Сервер передаёт модели чек-лист и транскрипт, где у каждой реплики есть ID (`m1`, `m2`, … — по порядку исходного массива).
2. Модель возвращает по каждому критерию ответ, объяснение, цитаты и проверенный участок (структурированный JSON).
3. Сервер проверяет ответ: все критерии на месте, значение допустимо (N/A — только где разрешён, шкала — только из списка ступеней), каждая цитата **дословно** есть в указанной реплике. При ошибке модель получает перечень проблем и одну попытку исправить ответ.
4. Если цитаты так и не подтвердились — статус «Требует проверки» с перечнем проблем.
5. **Баллы считает сервер**, а не модель (Decimal): «Да» — полный вес, «Нет» — 0, шкала пропорционально весу (верхняя ступень = полный вес), вес критериев с N/A перераспределяется (максимум 100), итог округляется до двух знаков; если применимых критериев нет — итог не считается. Грубая ошибка — отдельный флаг, итог не обнуляет.
6. Ошибка модели или сети никогда не превращается в нулевую оценку: статус «Ошибка», а при наличии запасной модели — повтор ею.

### Звонки: анализ записи

Если задан `GEMINI_API_KEY`, звонок оценивается **по аудиозаписи вместе с транскриптом**. Сервер берёт mp3 со страницы плеера организаторов (только с их сервера, до 18 МБ) и передаёт его модели `GEMINI_MODEL`. Модель:
- оценивает критерии по тому, что прозвучало: тон, паузы, перебивания, ясность речи;
- заполняет блок «Речь оператора по записи звонка»: интонация, дикция и грамотность, темп и паузы, вежливость, замечания;
- отмечает места, где расшифровка ошиблась («Вероятно сказано: …»). Такие ошибки не засчитываются оператору.

Цитаты по-прежнему берутся дословно из транскрипта и проверяются сервером. Временные ошибки Google (429, 5xx) повторяются с паузой, одновременно анализируется не больше двух записей (`AUDIO_CONCURRENCY`). Если запись недоступна или Gemini не ответил, звонок оценивается по тексту основной моделью, а в карточке указана причина. Выключить анализ звука: `AUDIO_ANALYSIS=off`.

## Сдача результатов организаторам

Формат JSON 1.0 из приложения к гайду: `results/dev/results.json` (DEV, 65 диалогов — уже в репозитории) и `results/prod/results.json` (10 контрольных чатов).

- Коды критериев: `contact, discovery, identification, consultation, empathy, dialogue, closure, critical` (во внутреннем чек-листе это `c1…c8`).
- `value`: `true` / `false` / `null` (N/A) или ступень шкалы до учёта веса; `evidence_turns` — номера реплик с 1 по исходному транскрипту, включая клиента, бота и события.
- `score.final_score` — итог 0–100 с двумя знаками, `critical_flag` совпадает с критерием `critical`.
- `model` — фактически использованные модели, `mode: external_api`; `team_name` — из `TEAM_NAME`.
- Диалог без оценки попадает в файл со `status: "error"`, пустыми `criteria`, `score: null` и причиной — не с нулём.
- По умолчанию выгружается оценка модели; флажок «С учётом апелляций» — с решениями проверяющих.

**Контрольный час:** ввести выданный `group_id` → «Загрузить из API организаторов» → «Оценить неоценённые» → «Проверить» (ровно 10 записей) → «Сохранить в репозиторий» (`results/prod`) → `git add results && git commit -m "Prod results" && git push`. На копии базы весь цикл занял около 32 секунд.

## Модели и стоимость

| Что оценивается | Модель | Режим |
|---|---|---|
| Чаты | OpenAI `gpt-6-luna` — модель с рассуждением (в интерфейсе можно выбрать `gpt-4o-mini`, `gpt-4.1-mini`, `gpt-4.1`, `gpt-4o`) | external_api |
| Звонки | Google `gemini-3.8-flash` по аудиозаписи + транскрипту; без ключа Gemini — по тексту моделью для чатов | external_api |

**Примерная стоимость одной оценки** с учётом всех вызовов (включая попытку исправления), по замеру на DEV:

| Диалог | Токены (вход / выход) | Стоимость |
|---|---|---|
| Чат (`gpt-6-luna`) | ≈ 2 100 / 1 400 (с токенами рассуждения) | ≈ $0,0009 |
| Звонок по тексту (без ключа Gemini) | ≈ 7 500 / 2 000 | ≈ $0,002 |
| Звонок по записи (3–7 мин аудио) | ≈ 13–22 тыс. / 3,6–4,6 тыс. | ≈ $0,02–0,03 |
| Весь DEV (60 чатов + 5 звонков по записи) | 212 тыс. / 106 тыс. | ≈ $0,20 |

Цены: `gpt-6-luna` — $0,10 вход / $0,50 выход за 1 млн токенов (токены рассуждения оплачиваются как выход); `gemini-3.8-flash` — $0,75 / $3,75 (вводной тариф Google до 31.12.2026, звук по цене текста, около 25 токенов на секунду записи). Расход токенов и стоимость видны в карточке каждой оценки и в «Аналитике».

## Настройки (.env)

| Переменная | Назначение |
|---|---|
| `TEAM_NAME` | Название команды в `results.json` |
| `ORGANIZER_API_URL` | Ссылка GET на API организаторов |
| `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_MODELS` | Ключ OpenAI, модель по умолчанию, список моделей для выбора |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | Ключ и модель Gemini (звонки и запасная модель) |
| `AUDIO_ANALYSIS`, `AUDIO_CONCURRENCY` | Анализ записей звонков (`on`/`off`) и сколько записей одновременно |
| `LLM_PROVIDER`, `LLM_FALLBACK` | Основной и запасной провайдер |
| `EVAL_CONCURRENCY` | Сколько диалогов оценивать параллельно |
| `DATABASE_PATH`, `PORT` | Путь к базе SQLite и порт сервера |

Ключи читаются только сервером и не передаются в браузер. Файл `.env` и база `data/` не попадают в Git.

## Ограничения

- Авторизации нет: методичка её не требует, прототип рассчитан на локальный запуск. Для публичного размещения нужен вход, иначе любой сможет тратить ваши ключи.
- Эталонных оценок для DEV нет, поэтому точность относительно Ground Truth заранее не измерена.
- Позиция реплики в записи звонка вычисляется по меткам времени с учётом пауз записи — она приблизительная.
- Бесплатный уровень Gemini ограничен числом запросов в день; при исчерпании звонки оцениваются по тексту.

## Почему `gpt-6-luna`

На 12 одинаковых чатах DEV сравнили `gpt-4o-mini` и `gpt-6-luna`: модели разошлись в 37 ответах из 96, и при сверке с текстом диалогов почти везде ближе к правилам чек-листа оказалась Luna. Она правильно ставит N/A в «Выявлении потребности», когда уточнять было нечего; не требует эмпатии там, где клиент не выражал недовольства; строже к «Завершению» (нужен итог или предложение помощи и прощание). Стоимость чата выросла с ≈ $0,0007 до ≈ $0,0009. Объяснения всегда на русском: сервер возвращает модели ответ на исправление, если объяснение написано на другом языке.
