# Архитектура

## Общая схема

```
Браузер (web/: HTML + CSS + JS)
      │  только относительные пути /api/...
      ▼
FastAPI (app/main.py) ───── SQLite (data/cqa.sqlite)
      │                       диалоги · версии чек-листа · оценки · апелляции
      ├── app/dataset.py, app/importers.py ── API организаторов / файлы
      ├── app/evaluator.py ── app/llm.py ──── OpenAI (чаты, текст)
      │                                  └─── Gemini (звонки: запись + транскрипт; запасная модель)
      ├── app/media.py ───── страница плеера организаторов → mp3
      ├── app/scoring.py ─── расчёт баллов и итога
      └── app/results.py ─── results/{dev,prod}/results.json (формат JSON 1.0)
```

Ключи моделей и ссылка на API организаторов хранятся только на сервере (`.env`) и не уходят в браузер.

## Поток оценки одного диалога

1. `POST /api/evaluations` создаёт запись оценки со статусом `queued` и сразу возвращает её ID. Оценка выполняется в фоне; одновременно идут не больше `EVAL_CONCURRENCY` оценок.
2. Для звонка с записью, если есть ключ Gemini, сервер скачивает mp3 (`app/media.py`).
3. `evaluator.evaluate` строит промпт: чек-лист выбранной версии и транскрипт с ID реплик `m1…mN`. Для звонка добавляются запись и инструкции по анализу речи.
4. Модель возвращает JSON по схеме: ответ, объяснение, цитаты (`message_id` + дословный фрагмент), проверенный участок; для звонка — блок `speech`.
5. `check_reply` проверяет ответ:
   - все критерии на месте, ответ допустим для типа критерия, N/A только где разрешён;
   - каждая цитата дословно входит в текст указанной реплики (без учёта регистра, лишних пробелов и типографики кавычек; допускается сокращение многоточием);
   - для «Да» и ненулевой шкалы нужна подтверждённая цитата; для «Нет» — цитата или проверенный участок.
6. Если структура неверна или цитаты не подтвердились, модель получает перечень ошибок и одну попытку исправить ответ. Не исправила цитаты → статус `needs_review`.
7. `scoring.compute` считает баллы (Decimal): вес, шкала, перераспределение N/A, округление, разделы, флаг грубой ошибки.
8. Результат, модель, версия промпта, токены, стоимость и анализ речи сохраняются. Ошибка всех провайдеров → статус `failed` без баллов.

Порядок провайдеров: для звонка — Gemini со звуком → основная модель по тексту → запасная. Для чата — выбранная или основная модель → запасная. Временные ошибки Gemini (429, 5xx) повторяются с паузами 4, 12 и 25 секунд; одновременно не больше `AUDIO_CONCURRENCY` запросов со звуком.

## Апелляции

- Апелляция привязана к оценке и критерию (одна на критерий). Исходные ответы модели никогда не перезаписываются.
- Финальный результат = исходные ответы + решения «изменить» по апелляциям; пересчитывается по той же версии чек-листа.
- `POST /api/appeals/{id}/preview` показывает итог до сохранения решения; `POST /api/appeals/{id}/decide` сохраняет решение с обязательной причиной.

## Данные (SQLite)

| Таблица | Содержимое |
|---|---|
| `conversations` | ID из API, набор (`group_id`), канал, язык, транскрипт (JSON с ID реплик), ссылка на запись |
| `checklists` | Версии чек-листа (JSON), комментарий, дата |
| `evaluations` | Диалог, версия чек-листа, статус, ответы по критериям, итог, разделы, флаг, проблемы проверки, модель, выбранная модель, токены, стоимость, анализ речи |
| `appeals` | Оценка, критерий, комментарий, статус, решение, новый ответ, причина |

Схема создаётся при запуске; новые столбцы добавляются миграцией без потери данных. Задачи, прерванные перезапуском сервера, помечаются как `failed`.

## API

| Метод и путь | Назначение |
|---|---|
| `GET /api/status` | Подключение API организаторов и моделей, список моделей, наборы, открытые апелляции |
| `POST /api/dataset/fetch` | Загрузить набор из API организаторов по `group_id` |
| `POST /api/dataset/upload?filename=…` | Импорт файла (JSON, CSV, TSV, XLSX, TXT) |
| `POST /api/dataset/import` | Импорт JSON в теле запроса |
| `DELETE /api/datasets/{group_id}` | Удалить набор с оценками и апелляциями |
| `GET /api/dataset/template.csv` | Шаблон CSV |
| `GET /api/conversations`, `GET /api/conversations/{id}` | Список диалогов с последней оценкой; диалог с историей оценок |
| `GET /api/conversations/{id}/audio` | Перенаправление на запись звонка |
| `GET/POST /api/checklists`, `GET /api/checklists/latest`, `GET /api/checklists/{id}` | Версии чек-листа |
| `POST /api/evaluations`, `POST /api/evaluations/batch`, `GET /api/evaluations/{id}` | Запуск оценки (одной или пакета, с версией чек-листа и моделью) и результат |
| `GET/POST /api/appeals`, `POST /api/appeals/{id}/preview`, `POST /api/appeals/{id}/decide` | Апелляции |
| `GET /api/analytics?group_id=` | Сводка для раздела «Аналитика» |
| `GET /api/results?group_id=`, `POST /api/results/save` | Результаты в формате JSON 1.0 и запись в `results/dev` или `results/prod` |
| `GET /api/export?group_id=` | Полная выгрузка оценок с апелляциями |

Интерактивная документация: `/api/docs`.

## Интерфейс

`web/index.html` содержит один корневой блок `#cqa-root`; `web/app.js` — маршрутизация по `#/…` и экраны «Диалоги», карточка диалога, «Аналитика», «Апелляции», «Чек-лист». Все расчёты — на сервере; в браузере хранится только выбранная модель (`localStorage`). Блок можно встроить как HTML-ресурс Dynamics 365, указав адрес сервера API.

## Тесты

`tests/` — 41 тест: расчёт итога и проверка чек-листа, сквозной сценарий API с подставной моделью (оценка, исправление ответа, выдуманная цитата, ошибка провайдера, запасная модель, апелляции), импорт всех форматов, формат `results.json`, выбор модели, удаление наборов, оценка звонка со звуком и откат на текст, стоимость аудио.
