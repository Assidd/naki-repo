# Сценарий защиты (5 минут)

Порядок — по плану из методички. Перед выступлением: приложение запущено (`start.bat`), DEV загружен и оценён, открыт раздел «Диалоги».

## Подготовка (до выхода)

- [ ] `start.bat` запущен, вверху справа два зелёных индикатора: «API организаторов» и «Модель ИИ».
- [ ] В левой панели выбрана модель (по умолчанию `gpt-6-luna`), под ней «Запасная: gemini-3.8-flash».
- [ ] В «Диалогах» только нужные наборы (DEV и контрольный); лишние удалены кнопкой корзины.
- [ ] `results/dev/results.json` и `results/prod/results.json` запушены (проверить на GitHub).
- [ ] В AI Studio остался запас запросов Gemini на живой показ звонка (1–2 запроса).
- [ ] Открыты вкладки: «Диалоги», карточки `p1-ru-001`, `p1-kz-001`, `p4-ru-003`, «Чек-лист».

## 1 минута — интерфейс и выбранный диалог

1. «Диалоги»: три шага процесса (загружено → оценено → спорные), фильтры по языку, каналу, статусу и «Только с грубыми ошибками».
2. Включить фильтр грубых ошибок → показать `p1-ru-022` (оператор предлагает перевести деньги на личную карту).
3. Открыть `p1-ru-001` (чат RU, вопрос о тарифе).

## 2 минуты — оценка, обоснование, переход к реплике, N/A, итог

1. Кольцо итога: **100 из 100**, разделы чек-листа, модель и стоимость оценки.
2. Критерий «Установление контакта» → нажать на цитату → транскрипт прокручивается к реплике `m10`, фраза подсвечена.
3. **N/A:** «Идентификация» — «Запрос не требовал идентификации», вес распределён между остальными критериями (видно «не учитывается (N/A)»).
4. Главное отличие: модель только выбирает ответы и приводит цитаты, **сервер проверяет, что каждая цитата дословно есть в диалоге**, и сам считает баллы по правилам чек-листа. Выдуманная цитата → статус «Требует проверки», а не тихий балл.
5. **Звонок** `p4-ru-003`: блок «Речь оператора по записи звонка» — интонация, дикция, темп, вежливость; в транскрипте пометки «Вероятно сказано: …» там, где расшифровка ошиблась (например, «направляющегозначного оттипе кот» → «направляю шестизначный OTP-код»). Ошибки распознавания не засчитываются оператору. Клик по цитате перематывает запись.

## 1 минута — апелляция, решение проверяющего, новый итог

1. Открыть `p1-kz-001` (казахский). «Выявление потребности» = **Нет**: клиент сразу назвал всё нужное, уточнять было нечего.
2. «Оспорить» → комментарий: «Данных хватало с самого начала — это N/A».
3. «Апелляции» → открыть → видны спорная оценка, объяснение модели, комментарий и фрагмент диалога.
4. «Изменить оценку» → N/A → причина → **итог пересчитывается ещё до сохранения** → «Сохранить решение».
5. В карточке: исходная оценка модели зачёркнута, новая отмечена, итог «было → стало».

## 1 минута — изменение критерия и применение чек-листа

1. «Чек-лист» → у критерия 5 поменять название и формулировку (или тип на шкалу) → «Сохранить новую версию» (появится v2).
2. Вернуться в диалог → выбрать «Версия чек-листа v2» → «Оценить заново» (~15 секунд для чата).
3. Показать: новый критерий оценён со своим объяснением, итог пересчитан, старая оценка осталась в «Истории оценок».

## Если спросят

- **Модели и стоимость:** чаты — OpenAI `gpt-6-luna` с рассуждением (≈ $0,0009 за чат; выбрана после сравнения с `gpt-4o-mini` на DEV), звонки — Google `gemini-3.8-flash` по записи (≈ $0,02–0,03 за звонок); модель выбирается в левой панели. Весь DEV — около $0,20.
- **Точность:** модель не считает баллы, только выбирает ответы; ответ проверяется (допустимые значения, N/A только где разрешён, цитаты дословно). При ошибке — одна попытка исправления, затем «Требует проверки». Звонки оцениваются по звуку, без штрафа за ошибки распознавания.
- **Ошибка модели:** статус «Ошибка», в `results.json` — `status: "error"`, никогда не ноль. Если Gemini недоступен, звонок оценивается по тексту, причина указана в карточке.
- **Сдача:** блок «Сдача результатов организаторам» → `results/dev` и `results/prod` в формате JSON 1.0.
- **Dynamics 365:** интерфейс — чистые HTML/CSS/JS в одном контейнере `#cqa-root`, API по относительным путям.
- **Аналитика:** раздел «Аналитика» — где операторы теряют баллы, распределение итогов, языки и каналы, грубые ошибки.

## Контрольный час (10 чатов)

Отрепетировано на копии базы: импорт → оценка → выгрузка заняли около 32 секунд.

1. В поле «Набор (group_id)» ввести выданный ID → «Загрузить из API организаторов».
2. Фильтр «Все наборы» → выбрать новый набор → выбрать модель → «Оценить неоценённые».
3. «Сдача результатов»: набор = контрольный, «Куда» = `results/prod` → «Проверить» (должно быть ровно 10 записей и 10 `ok`) → «Сохранить в репозиторий».
4. `git add results && git commit -m "Prod results" && git push` → открыть файл на GitHub и убедиться, что он там.
