# Требования организаторов и их выполнение

Источники: «CQA Hackathon — задание для участников» (4 стр.), «Чек-лист качества чатов» (3 стр.), «Приложение к студенческому гайду: как сдать результаты» (формат JSON 1.0), критерии отбора топ-50.

Обозначения: ✅ выполнено · ⏳ выполняется в день сдачи · ➖ не требуется.

## 1. Что должна уметь система (стр. 1)

| Требование | Статус | Где в системе |
|---|---|---|
| Пользователь настраивает чек-лист, загружает диалоги и запускает оценку оператора | ✅ | «Чек-лист», «Диалоги» → загрузка и «Оценить» |
| Система показывает баллы, объяснения и реплики, на которых основан вывод | ✅ | Карточка диалога: критерии, объяснения, цитаты с переходом к реплике |
| Пользователь оспаривает критерий; проверяющий изучает доказательства, подтверждает или меняет оценку и сохраняет финальный результат | ✅ | «Оспорить» в карточке → «Апелляции» → решение |

### Вес и итог (стр. 2 методички, стр. 2 чек-листа)

| Правило | Статус | Реализация |
|---|---|---|
| «Да» — полный вес, «Нет» — 0 | ✅ | `app/scoring.py` |
| Шкала пересчитывается пропорционально весу, верхняя ступень = полный вес | ✅ | Например, 15 из 20 при весе 20 = 15 баллов |
| N/A только где разрешён и выполнено условие | ✅ | Сервер отклоняет недопустимый N/A |
| Вес N/A перераспределяется пропорционально, максимум 100 | ✅ | Итог = сумма баллов / сумма применимых весов × 100 |
| Округление итога до двух знаков; нет применимых критериев — итог не считается | ✅ | Decimal, ROUND_HALF_UP; `score = null` |
| Грубая ошибка отмечается отдельно | ✅ | Флаг, баннер в карточке, фильтр, аналитика |
| Порог первой реакции 3 минуты, теги и вложения в оценку не входят | ✅ | Не используются в оценке |

## 8. Критерии отбора топ-50

| Критерий | Что сделано |
|---|---|
| **Точность AI-оценки** относительно Ground Truth (главный) | Модель только выбирает ответы, баллы считает сервер по правилам; проверка допустимых значений и N/A; дословная проверка цитат с попыткой исправления; звонки — по записи, без штрафа за ошибки распознавания; выбор более сильной модели в интерфейсе |
| Функциональность и уникальные возможности | Анализ речи по записи, проверка доказательств, аналитика, импорт форматов, выбор модели, запасная модель, учёт стоимости |
| Удобство использования | Пошаговый процесс на главной, подсказки «как читать», цветовые оценки, фильтр грубых ошибок, единый стиль Freedom Broker, адаптивная вёрстка |
| Корректность процесса: система действительно анализирует новые диалоги | Каждая оценка — настоящий вызов модели с сохранёнными моделью, версией промпта, токенами и стоимостью; цитаты сверяются с текстом |
| Разнообразие технических подходов | Облачные API: OpenAI для текста и Gemini для аудио |
